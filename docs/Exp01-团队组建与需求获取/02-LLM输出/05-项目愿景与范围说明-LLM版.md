# 项目愿景与范围说明（LLM 版，仅供对照）

> 生成工具：Claude Code，2026-09-14。指导书要求本文件"手动撰写"，因此本 LLM 版只用于组长手写版完成后的对比，不得直接改名提交。结构参考 Wiegers《软件需求》的愿景与范围文档。

## 1. 业务需求

### 1.1 背景

2025 年起《学位法》将利用人工智能代写列为学术不端。2026 年春季高校普遍对毕业论文启用 AIGC 检测，红线从 15% 到 40% 不等，但检测结果跨平台差异超过 20 个百分点，经典散文被判 AI 率超过 60%，认真写作的学生为"自证是人"反复付费。与此同时，教育部 2025 年 11 月《教师生成式人工智能应用指引》要求学生在作业中声明使用环节与具体方式，中国学位与研究生教育学会 2026 年 5 月指南要求声明写清工具、用途、环节、参数、验证过程。制度方向已从"事后检测"转向"事前备案、过程留痕"，但课程作业层面没有承载这一要求的工具，声明仍靠 Word 表格手填。

### 1.2 业务机会

为课程作业提供一个学生侧主动留痕、教师侧可见时间线、学院侧可校验证据包的平台，使"声明"从一张纸变成有据可查的过程材料，同时不做任何"是否作弊"的判定。

### 1.3 业务目标与成功指标

| 编号 | 目标                     | 指标                                                       | 测量时点     |
| ---- | ------------------------ | ---------------------------------------------------------- | ------------ |
| BO1  | 学生声明填写成为常规动作 | 试点课程作业提交时声明附带率 95% 以上                      | 第 12 周验收 |
| BO2  | 教师批改负担不增加       | 教师查看一份作业时间线平均用时 2 分钟以内                  | 第 12 周验收 |
| BO3  | 申诉有据可查             | 证据包导出后哈希校验通过率 100%；至少完成 1 次模拟申诉演练 | 第 12 周验收 |
| BO4  | 学生零成本自证           | 证据包导出用时 1 分钟以内，全程免费                        | 第 12 周验收 |

### 1.4 愿景陈述

对于需要在课程作业中规范使用 AI 的学生与教师，留痕是一个作业过程留痕与 AI 使用备案平台。它让学生几次点选就能登记 AI 使用并自动保存写作版本，让教师看到作业如何一步步形成，让学院在申诉时拿到可校验的证据包。不同于只给出一个概率数字的 AI 率检测，留痕只呈现事实、不作判定，把结论留给人。

### 1.5 业务风险

| 风险                       | 可能性 | 影响 | 缓解                                                     |
| -------------------------- | ------ | ---- | -------------------------------------------------------- |
| 学生认为是监控而抵制       | 中     | 高   | 快照学生侧触发，教师端不展示细粒度编辑流，默认权限最小化 |
| 教师不配置政策导致功能空转 | 中     | 中   | 提供三档预设模板，一次点选即可启用                       |
| 被误用为处分依据引发争议   | 低     | 高   | 界面与文档明确"事实材料之一"，不输出判定                 |
| 校内部署审批周期长         | 中     | 中   | 不依赖外部接口，Sprint 2 前回访信息中心                  |

## 2. 解决方案愿景

### 2.1 主要特性

| 编号 | 特性                     | 说明                                                    |
| ---- | ------------------------ | ------------------------------------------------------- |
| FE1  | 课程 AI 政策配置与展示   | 教师按禁止、需声明、鼓励三档配置，学生进入作业即见规则  |
| FE2  | 作业工作区与自动版本快照 | 学生在系统内编辑或导入文件，按时间与编辑量自动生成快照  |
| FE3  | AI 使用登记              | 几次点选登记工具、环节、用途，可粘贴提示词与输出        |
| FE4  | AI 使用声明生成          | 提交时自动汇总登记项生成声明，要素对齐 2026 年 5 月指南 |
| FE5  | 教师时间线               | 版本节点、粘贴段落来源、大幅改动标记、声明对照          |
| FE6  | 段落级贡献占比           | 人写、AI 粘贴、粘贴后修改三类占比（Sprint 2）           |
| FE7  | 证据包导出与校验         | 版本、登记、声明打包，哈希链校验（Sprint 2）            |
| FE8  | 学院复核工作台           | 申诉启动后复核员查看证据包与时间线（Sprint 2）          |

### 2.2 假设与依赖

- 假设学生愿意在系统内完成主要写作或定期导入版本。
- 假设试点课程教师愿意配置政策并在批改时查看时间线。
- 依赖校内 MySQL 与容器环境；统一身份认证在 Sprint 2 对接，Sprint 1 使用本地账号。

## 3. 范围与限制

### 3.1 Sprint 1 范围（第 5-8 周）

FE1、FE2、FE3、FE4、FE5 的基础版本：政策三档配置、学生工作区与自动快照、登记表单、声明生成、教师时间线（版本节点与粘贴标记）。

### 3.2 Sprint 2 范围（第 9-12 周）

FE6 贡献占比算法、FE7 证据包与哈希校验、FE8 复核工作台、大文本多版本差分性能优化、Docker 部署与统一身份认证对接。

### 3.3 范围外

- 不做 AI 生成内容检测或 AI 率计算。
- 不做文本查重。
- 不接入外部大模型接口，不把作业文本发送到任何外部服务。
- 不自动抓取学生与 AI 工具的聊天记录。
- 不安装桌面监控类客户端。
- 不覆盖毕业论文全流程管理，不替代现有毕设系统。
- 不做移动端原生应用。

### 3.4 限制与排除

- 时间：10 周两个 Sprint，每周一次实验课加课外时间。
- 人力：6 人，均为在校本科生。
- 技术：Spring Boot 3、Vue 3、MySQL 8，不引入需付费或需 GPU 的组件。
- 合规：学生作业文本仅存校内，权限分层，保存期限按教务口径。

## 5. 术语表

| 术语   | 定义                                                                   |
| ------ | ---------------------------------------------------------------------- |
| 快照   | 某一时刻作业文本的完整副本或相对上一版本的增量记录                     |
| 登记项 | 学生一次 AI 使用的记录：工具、版本、环节、用途、提示词、输出、采用方式 |
| 声明   | 提交时由登记项汇总生成的《AI 使用声明》                                |
| 时间线 | 按时间排列的快照节点、登记项与段落来源标记                             |
| 证据包 | 快照、登记项、声明及其哈希链的打包导出                                 |
| 三档   | 禁止使用、需声明使用、鼓励使用                                         |
