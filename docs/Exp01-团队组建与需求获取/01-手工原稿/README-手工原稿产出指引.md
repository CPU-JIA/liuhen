## 模拟访谈演练流程（约 90 分钟）

课程要求的是"模拟需求访谈"，用角色扮演完成即可。若能约到真实老师或教务人员，优先真实访谈。

1. 分角色。4 场访谈，每场 1 名扮演受访者、1 名提问、1 名记录，其余旁听并可补问。6 人轮换，保证每人至少记录一场。
2. 扮演者提前 10 分钟读 `02-LLM输出/03-模拟访谈脚本-完整问答.md` 对应角色，理解立场后脱稿回答，允许临场发挥和改口。
3. 提问者只带 `02-LLM输出/02-访谈提纲.md`，不看脚本答案。
4. 记录人用纸笔记原话与追问，每场结束 10 分钟内拍照并录入 `docs/templates/访谈记录模板.md`。
5. 每场结束提问者口述三条最强烈印象，记录人写在笔记末尾。
6. 四场结束后，文档与组长只依据手写笔记整理人工版纪要。

## 手写愿景与范围说明的最低要求

- 一段愿景陈述：对于谁、是什么、做什么、不同于什么。
- 三到五个业务目标，每个带一个可测量的指标。
- Sprint 1 与 Sprint 2 范围各一段。
- 范围外清单，至少五条。
- 主要风险，至少三条。

写完之后再打开 LLM 版，把差异写进 `03-对比与修改记录/对比记录-愿景与范围.md`。

## 常见错误

- 直接改写 LLM 版当手工原稿。抽查答辩时老师会问"这条需求来自哪场访谈的哪句话"，没有手写笔记答不上。
- 访谈时先介绍系统功能再提问，受访者会顺着功能说，得不到真实痛点。
- 笔记只记结论不记原话。原话是对比记录和用户故事的依据。
