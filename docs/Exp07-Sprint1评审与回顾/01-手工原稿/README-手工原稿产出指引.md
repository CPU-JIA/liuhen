# 手工原稿产出指引（实验 7）

> 指导书要求"团队演示 Sprint 1 功能，接受教师和同学提问，手写 Sprint 回顾改进项，每位学生提交个人述职，提交评审记录和回顾报告"。本实验 LLM 可做的事是"无"：演示脚本、问答记录、回顾便利贴、述职都是人手上的活。本目录放评审前后人先写的东西，最终版在 04。

## 顺序

1. 评审前一天彩排。演示脚本先写在纸上（谁操作、谁讲、点哪里、老师会看到什么、对应哪条验收），照着走一遍，卡住的地方当晚修，脚本改到第二版。
2. 评审课上张家森记原始问答：谁问的、原话、谁答的、答了什么、有没有当场答不上来。不整理，先记全。
3. 评审课后回顾会。每人三种便利贴：继续做、停止做、开始做。贴完投票，票多的写成改进项，每条要有负责人和"Sprint 2 怎么验证做到了"。
4. 述职各人自己写，组长不代笔。写自己干了什么、卡在哪、学到什么，数字从看板与提交记录里查，不凭印象。

## 演示的规矩

- 演示只用真实路径：登录、点、输入，不预先打开页面，不用接口工具代替界面。接口层的东西（删除接口不存在、教务 403）用 curl 演示，但要说明"这是界面上根本没有入口的东西"。
- 每一步说清对应的验收编号，老师问"这条怎么验的"能立刻指到冒烟脚本或测试用例的行。
- 演示数据评审前一晚准备好：一个课程、一份作业、三个学生账号；一个学生走完整流程，一个学生造 50 个版本 10 条登记（测渲染时间用），一个学生留着现场演示锁定。
- 不演示没做的功能，不说"这个 Sprint 2 会有"来带过问题。老师问到没做的，答"没做，记在停车场第几条"。

## 回顾会的规矩

- 只谈过程不谈人。"第 6 周进行中 15 张"是事实，"谁谁拖了"不说。
- 每条改进项必须能验证：Sprint 2 结束时拿什么证明做到了。写不出验证方式的改进项不立项。
- 数字从看板与 git 记录里查：计划小时、实际小时、每周完成数。凭印象的数字当场核对。
