## 最终版形成方式

以手写版为骨架，编号沿用手写版前缀（ACC / RULE / WRK / REG / DECL / TCH / EVD / APL / PERM），新增 STAT。并入 LLM 初稿两张（RULE-05、PERM-02），LLM 检查催生三张（ACC-04、REG-03 拆出、STAT-01、PERM-03），不采纳 LLM 初稿三张（SNAP-05、REG-04、TL-03）。最终 34 张卡，Must 16 张，比手写版多一张 ACC-04；Sprint 1 放 16 张 Must 加 4 张 Should（RULE-03、REG-02、REG-03、DECL-03），WRK-04 挪到 Sprint 2。故事点按工作坊决定在实验 4 用扑克牌估，本实验不估。

## LLM 的典型问题

- 误报 2 条（A-2、K-6），全在 LLM 自己标"拿不准"的三条里，说明它对自己的把握是准的。
- 把"我们没决定"当成"我们漏了"：M-7、M-10 这两条停车场里明明写着，LLM 仍列为缺失。对人来说停车场就是"知道但没定"，对 LLM 来说没成卡就是没有。
- 数字建议偏激进：初稿 5 分钟 / 300 字符的快照频率、20 万字符的文本上限，都不像是为课程作业定的。最终只采纳了它两个数字（100 字符、30%）。
- 优点也要记：M-1 登录缺失和 M-2 字段对不上，六个人两个小时都没发现，LLM 一遍就抓出来了。K-2 规则版本问题直接影响规则引擎设计，杨子航说这条值一次返工。

## 手写版的典型问题

- 一卡两事出现 3 次（REG-01、TCH-03、TCH-04），其中 REG-01 是真需要拆的。原因是写卡时按"用户一口气做完的事"写，没按"可独立交付的事"写。
