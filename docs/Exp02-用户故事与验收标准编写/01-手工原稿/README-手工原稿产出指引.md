# 手工原稿产出指引（实验 2）

> 指导书要求"根据需求访谈结果，手动编写用户故事卡"与"为每个用户故事编写验收标准"，并提交手工草稿。本目录放这些手写产物。写之前不要看 `02-LLM输出/01`、`02`，写完再看。

## 需要产出的文件

| 文件                 | 谁做               | 命名                  |
| -------------------- | ------------------ | --------------------- |
| 手写故事卡照片或扫描 | 全组               | 故事卡-手写-第N页.jpg |
| 用户故事卡-手工版.md | 文档录入           | 用户故事卡-手工版.md  |
| 验收标准表-手工版.md | 测试主笔，开发协助 | 验收标准表-手工版.md  |

## 故事编写工作坊（约 2 小时，6 人）

材料：便利贴或 A4 纸裁成卡片、马克笔、实验 1 的手写访谈笔记与人工版纪要。

1. 热身 10 分钟。文档把人工版纪要中的痛点与需求逐条读一遍，贴在墙上或桌面。
2. 分角色写卡 40 分钟。每人领一到两个角色：学生、任课教师、教务、复核员、系统管理员。每人对着纪要为自己的角色写故事卡，格式固定为"作为…我想要…以便…"，每张卡右上角写来源，例如"访谈三 小陈 Q5"。写不出来源的卡先放一边。
3. 贴墙归类 20 分钟。按功能把卡片分组，给每组起一个史诗名。重复的合并，写不出来源的讨论后保留或丢弃。
4. 排优先级 20 分钟。用 MoSCoW 四列，组长主持，每人两票投 Must。Must 超过 15 张要砍。
5. 分 Sprint 15 分钟。Sprint 1 只放 Must 和少量 Should，Sprint 2 放其余。
6. 拍照存档 5 分钟。整墙拍照，每张卡单独拍。
7. 录入 10 分钟。文档按 `docs/templates/用户故事卡模板.md` 录入，编号规则 US-史诗-序号。

## 验收标准编写（约 1.5 小时）

1. 测试主笔，两名开发配合，只写 Sprint 1 的 Must 故事。
2. 每个故事至少两条：一条正常路径，一条异常或边界。
3. 用 `docs/templates/验收标准表模板.md`。Then 里必须有能看见的结果，形容词必须换成数字，拿不准的数字先写一个并标"待定"。
4. 写完互换检查：开发看测试写的是否可实现，测试看开发补的是否可验证。

## 提交 LLM 检查之前

- 手写照片已上传，录入版已完成。
- 组长在录入版文件头写上完成时间，作为"先手写后 LLM"的证据。

## 手写完成后的顺序

1. 用 `02-LLM输出/03-用户故事检查清单与LLM检查方法.md` 的提示词把手写版交给 LLM 检查，结果原样存为 `02-LLM输出/04-LLM检查结果-针对手写版.md`。
2. 打开 `02-LLM输出/01`、`02` 作为第二份对照。
3. 逐条决定采纳与否，写入 `03-对比与修改记录/修改对比记录-用户故事与验收标准.md`。
4. 合并成最终版放 `04-最终版`。

## 常见错误

- 故事写成功能清单："系统提供快照功能"。要写成人的诉求。
- 一张卡两件事："学生可以登记并导出声明"。拆成两张。
- 验收写"系统应正确保存"。要写"停止输入 3 秒后页面显示已保存时间"。
- 没有来源的卡越写越多。没有来源就是拍脑袋，答辩会被问住。
