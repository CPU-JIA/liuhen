# 用户故事检查清单与 LLM 检查方法

> 生成工具：Claude Code，2026-09-14。对应指导书实验内容第 3 条"使用 LLM 检查用户故事和验收标准中的缺失、歧义或冲突"。第一部分是检查清单，第二部分是可直接复制的提示词，第三部分是对本目录 LLM 初稿自身做的一次示范检查，用来展示结果应该长什么样。对手写版的正式检查结果另存为 `04-LLM检查结果-针对手写版.md`。

## 一、检查清单

### 缺失

| 编号 | 检查项         | 怎么查                                                   |
| ---- | -------------- | -------------------------------------------------------- |
| M1   | 角色缺失       | 访谈纪要里出现的每类角色，是否至少有一个故事以其为"作为" |
| M2   | 需求缺失       | 纪要中每个 N 编号是否至少被一个故事追溯                  |
| M3   | 约束缺失       | 每个 C 编号是否体现在某个故事或验收标准中                |
| M4   | 反对意见缺失   | 每个 O 编号是否有对应的"不做什么"故事或范围外说明        |
| M5   | 异常路径缺失   | 每个 Must 故事是否至少有一条异常或边界验收标准           |
| M6   | 非功能需求缺失 | 性能、权限、数据保存期限是否有可测的标准                 |
| M7   | 首末环节缺失   | 用户从登录到导出的完整路径上是否有断点                   |

### 歧义

| 编号 | 检查项         | 怎么查                                         |
| ---- | -------------- | ---------------------------------------------- |
| A1   | 无数字的形容词 | 找"快速""大幅""及时""少量""合理"，要求换成数字 |
| A2   | 多义动词       | 找"处理""管理""支持""优化"，要求写出具体行为   |
| A3   | Then 不可观察  | 找"系统应正确""用户满意"，要求换成可见结果     |
| A4   | 角色不明       | "用户"要拆成学生、教师、复核员、教务、管理员   |
| A5   | 一个故事多件事 | "并且""同时""以及"连接的两个动作要拆           |
| A6   | 术语不一致     | 同一概念是否有多个叫法：版本 / 快照 / 存档     |

### 冲突

| 编号 | 检查项         | 怎么查                                   |
| ---- | -------------- | ---------------------------------------- |
| K1   | 故事之间冲突   | 一个故事要求删除，另一个要求不可删       |
| K2   | 故事与约束冲突 | 自动记录与"学生侧触发"是否矛盾           |
| K3   | 优先级冲突     | Must 故事依赖 Should 故事                |
| K4   | 权限冲突       | 某角色在一个故事可见、在另一个故事不可见 |
| K5   | 与范围外冲突   | 故事是否偷偷做了范围外声明不做的事       |

## 二、检查提示词（复制使用）

把手写版故事卡与验收标准全文贴在下面这段话之后：

```
你是软件需求评审员。下面是一组用户故事与验收标准，来自一个"课程作业 AI 使用备案与过程证据链平台"项目。请只做检查，不要重写故事。

按以下三类逐条列出问题，每个问题写：编号、涉及的故事编号、问题描述、为什么是问题、建议的修改方向（一句话）。

1. 缺失：角色缺失、需求未被覆盖、约束未体现、Must 故事缺异常路径、非功能需求无数字、用户路径有断点。
2. 歧义：无数字的形容词、多义动词、Then 不可观察、角色笼统、一个故事包含多件事、术语不一致。
3. 冲突：故事之间、故事与约束之间、优先级依赖倒置、权限前后不一、与范围外清单矛盾。

最后给一个统计表：三类各多少条，其中你认为必须在实验 2 内修的有几条。

附：本项目的约束清单如下（贴入实验 1 纪要中的 C 与 O 编号内容）。
```

检查结果原样保存，包括 LLM 说错的地方，因为"LLM 检查中的误报"本身就是对比记录的素材。

## 三、示范：对本目录 LLM 初稿的自检结果

以下是把 `01-用户故事卡-LLM初稿.md` 与 `02-验收标准-LLM初稿.md` 用上面的提示词检查得到的结果。它证明 LLM 初稿本身也有问题，手写版不必以它为标准。

### 缺失

| 编号 | 故事       | 问题                                           | 为什么                                                             | 建议                                                       |
| ---- | ---------- | ---------------------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------- |
| M-1  | 全部       | 缺少"教师批量查看全班声明汇总"的故事           | 访谈一 T 老师提到 50 多份作业逐份看成本高，只有单份时间线不解决 P3 | 新增 US-TL-05：教师查看作业下全班声明一览表                |
| M-2  | 全部       | 缺少"学生在系统外写作后如何补录过程"的完整路径 | US-SNAP-04 只解决导入一个版本，导入多个历史版本无说明              | 在 US-SNAP-04 验收中补"可连续导入多个文件并按上传顺序排列" |
| M-3  | US-SEC-01  | 缺少数据保存期限的验收标准                     | 纪要 C3 明确保存至毕业后一年，但无故事承接                         | 新增 US-SEC-04：到期数据归档与删除，Sprint 2               |
| M-4  | US-POL-01  | 缺少政策变更的历史记录                         | 教师中途改政策，学生按旧政策登记的部分如何评价没有依据             | 验收补"政策每次修改保留版本与时间"                         |
| M-5  | US-REG-01  | 未说明登记的"版本"字段来源                     | 声明要素要求工具版本，表单四个必填里没有版本                       | 版本设为可选字段，声明中缺失时显示"未填写"                 |
| M-6  | US-ATTR-01 | 缺少异常路径                                   | 全文被一次性粘贴的极端情况如何归因未说明                           | 补"全文单次粘贴时整篇标为 AI 粘贴或外部来源，由学生选择"   |

### 歧义

| 编号 | 故事       | 问题                     | 为什么                                   | 建议                                                       |
| ---- | ---------- | ------------------------ | ---------------------------------------- | ---------------------------------------------------------- |
| A-1  | US-TL-03   | "大幅改动"在故事中无数字 | 验收给了 30%，故事正文仍是形容词         | 故事正文改为"改动量超过可配置阈值，默认 30%"               |
| A-2  | US-REG-01  | "几十秒内"不可测         | 验收用"5 次点选"替代了，但两者不是一回事 | 统一为"5 次点选内且不含可选字段时 30 秒内可完成"           |
| A-3  | US-SNAP-03 | "一定长度"               | 验收给了 100 字符，故事没给              | 故事正文写明 100 字符                                      |
| A-4  | 全部       | "版本"与"快照"混用       | US-TL-02 说版本，US-SNAP-02 说快照       | 统一：快照是存储单位，版本是给用户看的快照序号，文档中标注 |
| A-5  | US-DECL-01 | "验证方式"含义不清       | 学生不知道填什么                         | 提供选项：核对原文、运行测试、与教材比对、未验证           |

### 冲突

| 编号 | 故事                                 | 问题                                       | 为什么                 | 建议                                                                                         |
| ---- | ------------------------------------ | ------------------------------------------ | ---------------------- | -------------------------------------------------------------------------------------------- |
| K-1  | US-SNAP-02 与 C5                     | "自动快照"与"学生侧触发"看似矛盾           | 学生会问：自动就是监控 | 明确：自动快照仅在学生进入工作区并开始编辑后进行，离开工作区即停止，且学生可随时查看全部快照 |
| K-2  | US-REG-03 与 US-EVID-01              | 登记可修改与哈希链不可篡改                 | 修改后旧哈希如何处理   | 修改作为新记录追加，旧记录标记作废但保留，链不断                                             |
| K-3  | US-DECL-01 与 US-SEC-01              | 声明含提示词全文，教务可见统计是否含提示词 | 提示词可能含个人信息   | 统计口径只含数量与档位，不含任何文本                                                         |
| K-4  | US-TL-03 与 US-TL-04                 | "加粗标记大幅改动"可能被学生视为风险标红   | 与"只呈现事实"边界模糊 | 标记用中性样式与文案"改动量 35%"，不用颜色暗示                                               |
| K-5  | US-ACC-01 Must 依赖 US-ACC-03 Should | Sprint 1 无统一认证时账号从哪来            | 优先级依赖倒置         | 明确 Sprint 1 用本地账号，US-ACC-01 验收补"支持管理员批量导入账号"                           |

### 统计

| 类别 | 条数 | 建议实验 2 内必修 |
| ---- | ---- | ----------------- |
| 缺失 | 6    | M-1、M-3、M-5     |
| 歧义 | 5    | A-1、A-2、A-4     |
| 冲突 | 5    | K-1、K-2、K-5     |

### 对这份自检的提醒

LLM 的检查也会误报。例如 K-3 假设教务能看到提示词，其实 US-SEC-01 已写教务只看统计，这条更接近"需要在验收中说清统计口径"而不是冲突。人工复核时应逐条判断"这是真问题、是表述问题、还是误报"，并把判断写进对比记录。
