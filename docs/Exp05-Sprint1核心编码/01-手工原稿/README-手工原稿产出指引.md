# 手工原稿产出指引（实验 5）

> 指导书要求"使用 LLM 生成框架代码，学生手写核心算法和业务逻辑，记录人工修改过程，小组内代码走查"。本目录放手写算法的草稿照片与录入版、走查时的纸面记录。

## 什么算"框架代码"，什么必须手写

| 可以让 LLM 生成                                  | 必须手写                                                        |
| ------------------------------------------------ | --------------------------------------------------------------- |
| pom.xml、application.yml、启动类                 | MyersDiff（字符级、行级、apply）                                |
| JPA 实体、仓库接口、DTO 记录类                   | DeltaCodec                                                      |
| Spring Security 配置骨架、JWT 过滤器骨架         | HashChainService                                                |
| Controller 的路由与参数绑定骨架                  | PolicyRuleEngine                                                |
| Vue 项目脚手架、路由、axios 封装、页面布局与样式 | SnapshotService 的触发与关键帧策略、reconstruct                 |
| 统一异常处理骨架                                 | AccountService 的登录锁定、名单导入校验                         |
|                                                  | WorkService、RegistrationService、DeclarationService 的业务规则 |
|                                                  | AccessControl 的矩阵与对象归属判断                              |
|                                                  | 前端编辑器的自动保存、断网缓存、粘贴检测                        |

判断标准：删掉这段代码，系统还能不能"只呈现事实、留下证据"。不能就是核心，必须手写。

## 手写算法的顺序

1. 先在纸上推一个小例子（Myers 用论文的 ABCABBA → CBABAC），确认自己能手算出 D 和路径。
2. 写测试：先写"apply(diff(a,b)) == b"这一条，再写边界。
3. 写实现，跑测试，不过就回纸上找。
4. 写完再看 LLM 建议的库（java-diff-utils）的接口设计，只对比接口，不看实现。

## 人工修改记录怎么写

每一处对 LLM 生成代码的修改都记：文件、LLM 原来怎么写、改成什么、为什么。编译错误和测试失败也记，那是最有说服力的"人工过程"。

## 走查怎么开

每人 20 分钟讲自己的核心代码，其余人对着验收标准和设计说明挑毛病。记录人写：谁讲、谁提、问题、改不改、谁改。走查不评价人，只评价代码。
