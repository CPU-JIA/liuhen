## 第 1 页：问题与论文的核心想法

要解决的事：两版文本 a、b，求把 a 变成 b 的最少增删（D），并且要能反过来从 a 加脚本还原 b。存快照时只存脚本。

Myers 1986 的想法：在编辑图上找从 (0,0) 到 (N,M) 的最短路径。往右一步 = 删 a 的一个字符，往下一步 = 插 b 的一个字符，对角线 = 相同字符，免费。第 d 轮只考虑走了 d 步非对角线的最远点。用对角线编号 k = x - y，V[k] 记录第 d 轮在第 k 条对角线上能到的最远 x。

每一轮 k 从 -d 到 d 步进 2。选择：

- k == -d，或者 k != d 且 V[k-1] < V[k+1]：从 k+1 往下走一步，x = V[k+1]
- 否则从 k-1 往右走一步，x = V[k-1] + 1
  然后沿对角线滑到底（snake）。x >= N 且 y >= M 就找到了，D = d。

时间 O((N+M)D)，D 小的时候几乎是线性。自动保存场景 D 就是小的。

## 第 2 页：手算论文例子 ABCABBA → CBABAC

N = 7，M = 6。V 数组每轮记录（只写关键值）：

| d   | k 范围 | V 中到达的 x（按 k）                                                                                                 | 到没到终点 |
| --- | ------ | -------------------------------------------------------------------------------------------------------------------- | ---------- |
| 0   | 0      | k=0: x=0（A 对 C，不同，滑不动）                                                                                     | 否         |
| 1   | -1,1   | k=-1: x=0,y=1 滑到 (1,2)? 不对，重算：k=-1 从 V[0]=0 往下，(0,1)，a[0]=A b[1]=B 不同；k=1：(1,0)，a[1]=B b[0]=C 不同 | 否         |
| 2   | -2,0,2 | k=-2:(0,2) 滑 A=A→(1,3)；k=0:(1,1) B=B→(2,2)；k=2:(2,0) C=C→(3,1)                                                    | 否         |
| 3   | -3..3  | k=-3:(1,4)，k=-1:(2,3) A=A→(3,4)，k=1:(3,2) A=A→(4,3) B=B→(5,4)，k=3:(4,1)                                           | 否         |
| 4   |        | k=-2:(3,5) …；k=0:(5,5) A? a[5]=B b[5]=C 不同；k=2:(6,4) A=A→(7,5)                                                   | 否         |
| 5   |        | k=1:(7,6) 到终点                                                                                                     | 是，D = 5  |

纸上第二轮算错过一次，把 snake 滑过头了，后来重算。这也是为什么测试里放了这个例子断言 D = 5。

回溯：从终点倒着看每一轮的 V，判断上一步是从 k+1 下来还是从 k-1 右来，先把对角线部分倒着记为 EQUAL，再记那一步 INSERT 或 DELETE。倒着记完再整体反转。

## 第 3 页：工程上的三个决定

1. 先剥公共前缀和后缀。自动保存的两版通常只是中间改了几句，剥完 N、M 都很小。这是最省事也最有效的优化。
2. 回溯要保存每一轮的 V 数组，内存是 D 的平方级。定上限 D = 3000，超过就退化成"删掉中间全部、插入中间全部"。理由：3000 步以上的差分存下来也比全文小不了多少，而且教师端对比用的是行级。退化必须是显式的，测试里有一条专门验它。
3. 字符按 Unicode 码点比，不按 char。emoji 是代理对，按 char 会切一半，还原出来是乱码。测试里放了 😀。

行级 diff：把每行映射成整数（HashMap 编号），跑同一个核心。给教师端高亮用，行数少，D 不会大。

apply 的边界：EQUAL 和 DELETE 只消费 base 的码点数，不比内容。原因是 DeltaCodec 为了省空间只存长度。安全靠快照的 content_hash：还原完对不上就抛异常，宁可报错也不给假文本。
