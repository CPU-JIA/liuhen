## 第 1 页：哈希链

要保证的事：快照和登记写进去以后，任何人改任何一条，事后都能发现，并且能说出"从第几条开始不可信"。

公式：chainHash_i = SHA-256( chainHash_{i-1} ‖ payloadHash_i ‖ 毫秒时间戳_i )

- payloadHash 是这条记录内容的 SHA-256。快照用全文哈希，登记用九个字段拼起来的哈希。
- 第一条的 chainHash_{i-1} 是 64 个 0，叫 GENESIS。
- 同一份作业稿两条链：work:{id}:snapshot、work:{id}:registration。分开是因为两种记录的写入节奏不同，混一条链谁都得等谁。

验证：从头重算。第 i 条要满足两件事，prev 等于上一条的 chainHash，重算出来的 chainHash 等于存的。哪一条先不满足就返回 i。返回 -1 表示全部通过。

三种篡改的表现：

1. 改第 i 条内容：第 i 条重算对不上，断在 i。
2. 删第 i 条：第 i+1 条的 prev 对不上，断在 i（删后它就是第 i 条）。
3. 改时间戳：时间戳参与哈希，断在 i。

为什么时间戳要进哈希：不进的话可以把一条记录的时间往前挪，让"写了很久"看起来像真的。虽然我们不评价时长，但证据的时间本身要不可改。

实现只用 JDK 的 MessageDigest，不引第三方库。输入校验：prev 和 payload 必须是 64 位十六进制，不是就抛异常，不让脏数据进链。

## 第 2 页：规则引擎

三件事：当前生效版本、一条登记是否超出允许范围、学生要不要重新确认。

当前版本：先找作业级（scope_assignment_id = 作业 id）最新一条，没有再找课程级（= 0）最新一条。Sprint 2 的作业级规则不用改引擎，只是多插几行。

判定真值表（场景 = 登记的"使用环节"对应的场景名）：

| 档位      | 场景显式允许 | 场景显式不允许 | 场景没提 |
| --------- | ------------ | -------------- | -------- |
| FORBID    | 不允许       | 不允许         | 不允许   |
| DECLARE   | 允许         | 不允许         | 不允许   |
| ENCOURAGE | 允许         | 不允许         | 允许     |

"没提"要单独标出来（explicit = false），界面上"老师明确禁止"和"老师没提"要区分，不然学生会觉得被冤枉。

环节到场景名的对应写死在 Stage 枚举里：查资料、生成大纲、生成正文、生成代码框架、生成数据、改语法、其他。老师配规则时勾的就是这几个名字，加自定义的。

要不要重新确认：对当前版本没有 ack 记录就要。老师发新版本，旧版本的 ack 自然失效，不用删任何东西。

声明按哪个版本对照：提交那一刻取到的版本，由 DeclarationService 传进来。引擎自己不再查一次，避免两次查询之间老师又发了一版。
