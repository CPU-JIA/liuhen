### 二.4 第 5 轮：集成测试两条

```
SprintOneMainLineTest.changedPasswordIsWhatTheNextLoginChecks
cn.liuhen.common.ApiExceptionHandler$BadRequestException: 账号或密码不正确
	at cn.liuhen.account.AccountService.login(AccountService.java:89)

SprintOneMainLineTest.mainLineFromRulesToDeclarationAndTimeline
org.opentest4j.AssertionFailedError: expected: <SUBMIT> but was: <EDIT_VOLUME>
```

第一条是产品 bug D-1：改密方法改的是控制器在事务外查出来的脱管实体，只改字段不 save，新密码与"已改密"标记都没落库。审查 Z-3 猜到了，这条用例证实了。冒烟脚本改完密一直用旧令牌往下走，从没用新密码再登录，所以实验 5 没发现。修法：`users.save(actor)`，单测补 `verify(users).save(student)`，冒烟脚本补"新密码能登录且不再要求改密""旧密码失效"两条。修：杨子航。

第二条是测试假设错：主线里第二次保存已经按改动量落了第 2 版，之后文本没变，提交时按走查第 4 条的设计不再重复存 SUBMIT 快照，最后一版自然是 EDIT_VOLUME。改法：提交前再保存一小句（不到 500 字符、不到 10 分钟，不落版本），这样提交才真的需要强制 SUBMIT 快照，用例才测到强制那条路径。判断：周浩然；改：袁飞翔。

## 四、前端

前端初稿四个文件在第一次运行前复制到 `02-LLM输出/01-测试代码初稿/frontend/src/`。

第一次运行 EditorView.test.ts 整个文件加载失败：

```
Error: [vitest] There was an error when mocking a module. ...
Caused by: Error: [vitest] No "createRouter" export is defined on the "vue-router" mock.
Did you forget to return it from "vi.mock"?
 ❯ src/router.ts:4:23
 ❯ src/api.ts:4:1
```

原因：`vi.mock("../api")` 的工厂用 `importActual` 加载了真 api.ts，它 import router.ts，router.ts 要 `createRouter`，而初稿把 vue-router 整个桩成只剩 `useRouter`。改法：部分桩，`{ ...actual, useRouter: () => ({ push }) }`，6 行。改：丁浩然。

第二处不是测试文件：`pnpm scan:words` 把 forbidden-words.test.ts 扫出 11 处命中，它必须写这些词来测清单。改扫描脚本跳过 `*.test.ts`，加注释说明测试文件不是用户会看到的文案。改：丁浩然。

其余三个测试文件初稿一次通过，没改。

TC-FE-12（保存在途时再输入）第一次能跑起来就失败，其余 25 条通过：

```
 × 自动保存状态机 > 保存请求在途时的新输入不能被成功回调抹掉（审查发现）
   → expected '已保存 10:20:30' to be '有未保存的修改，停止输入 5 秒后自动保存'
 Tests  1 failed | 25 passed (26)
```

这条失败是审查意见 F-1 的证据，改的是 EditorView.vue 不是测试。修后 26 条全过。

两处值得记的坑（没出错，但差点）：假定时器只 fake setTimeout / clearTimeout / setInterval / clearInterval，不碰 queueMicrotask 与 nextTick，否则 flushPromises 与 Vue 的 nextTick 会卡住；jsdom 没有 ClipboardEvent，粘贴用普通 `Event("paste")` 再 `defineProperty` 挂 `clipboardData.getData`。

## 五、这次学到的

- 初稿的 14 个后端文件里 8 个一行没改，改的 6 个合计 54 行差异，其中 17 行是录入转义。LLM 翻译用例表这件事做得可以，判断失败原因这件事它没参与。
- 9 条首跑失败里 6 条是产品问题，5 条是设计会上就标了"可能失败"的。用例表里"打到数据库才报错的输入一律写成服务层应拒绝"这条规矩值回票价。
- 单测抓不到改密不落库，因为单测里 save 与不 save 看起来一样；集成测试一条"改完再登录"就抓到。两种测试各管一段，谁也替不了谁。
