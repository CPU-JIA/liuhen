# 实验 3 实验报告

> 课程：软件工程　班级：24 软工 2 班　小组：留痕　组长：孟甲
> 实验名称：系统架构与数据库设计（含手工建模）　开设周次：第 4 周　完成日期：2026-09-14

## 一、实验目的

手动绘制系统类图与数据库 ER 图；使用 LLM 根据 ER 图生成 SQL 建表脚本初稿；人工优化 SQL 并保留优化前后对比；提交系统架构设计说明与设计稿。

本组要解决的具体问题：把实验 2 最终版的 34 张故事卡与 75 条验收标准落成一套能跑的数据库和一张能指导实验 5 编码的类图，并把四个手写算法在架构里安好位置。

## 三、实验过程

### 3.1 人工阶段

实验 2 对比会结束后没散，直接线上开实验 3。先全组过一遍 34 张卡，把名词圈出来：用户、课程、作业、规则、场景、作业稿、快照、粘贴、登记、工具、声明，加上 Sprint 2 的归因、证据包、申诉、审计。张家森把这张名词纸拍了照。

然后分头画。孟甲画架构：三个容器一个进程，按史诗分包，四个手写算法标粗。周浩然画类图，第一页领域类，第二页服务类，他坚持把 Controller 和 Repository 省掉，说模板化的东西不占纸。杨子航画 ER 图，用 Chen 氏记法，实体矩形、属性椭圆、联系菱形，键属性画下划线，弱实体双框。丁浩然列前端页面和接口清单。袁飞翔拿着验收标准表逐条对图，找图上没有的字段。

互相挑毛病，挑出来三处：袁飞翔发现粘贴事件没记位置，Sprint 2 归因做不了，杨子航加了 offset_start 和 offset_end；类图上枚举值没写全，定了两张图共用一张枚举表；杨子航提出规则不能是一个实体，得是"规则版本"，因为实验 2 的 K-2 定了声明按提交时版本对照。

张家森录入完成。类图用 Mermaid，ER 图用 Graphviz DOT，DOT 能把 Chen 氏的双框和下划线都表示出来。机房没装 Graphviz，所以录入版同时附了实体表、联系表、枚举表，内容一致。

### 3.2 LLM 辅助阶段

工具与版本：Claude Code，模型 Claude Fable 5.1，2026-09-14。操作人：孟甲。

输入：ER 图录入版的实体表、联系表、枚举表，以及验收标准中与数据有关的条目。提示词原文见 02-LLM输出/00-本目录说明.md。

输出：19 张表的建表脚本和一份设计假设说明。

未使用 LLM 的环节：类图、ER 图、架构图的绘制；SQL 的逐条优化决定；验证脚本的编写与执行；本报告正文。

### 3.3 对比与修改阶段

周浩然、杨子航在 LLM 生成的同时已按 ER 图批注列好了要改的清单，初稿一出来对着清单红笔批，批完改文件。30 条改动，按类别是结构 11、约束 8、类型 7、红线 1、整理 3。最重要的四条：快照从存全文改成关键帧加差分；规则从原地更新改成版本表；登记从原地更新改成追加加作废；所有外键从级联删除改成禁止删除。红线那条是 LLM 自己加了个"累计写作时长"字段，实验 1 的红线明确不要，删了。

杨子航坚持给快照、登记、声明加了六个触发器，数据库层面挡删除和修改。周浩然一开始觉得应用层挡住就够，最后同意，理由是答辩时直接在库里 DELETE 一条给老师看报错更有说服力。

袁飞翔在本机用 MySQL 8.4 二进制起了一个独立实例跑脚本。LLM 初稿能跑，19 张表，但库字符集是三字节的 utf8，8.4 报弃用警告。优化版 Sprint 1 加 Sprint 2 跑通，20 张表、2 个视图、6 个触发器。验证脚本 17 条断言全部符合期望，其中 7 条是故意触发报错的，比如删快照报"snapshot 不可删除"，改登记正文报"只允许把 status 置为 VOIDED"。

## 六、个人体会

- 周浩然：画类图的时候我才真正想清楚差分怎么存：关键帧每 10 个一次，中间存差分，重建就是找最近关键帧往后 apply。这个决定直接写进了 snapshot 表的 CHECK 约束，LLM 初稿存全文的写法和验收标准 30% 那条根本对不上。另一个收获是 DeltaCodec 单独拆出来，实验 9 想换编码不用动别的。
- 杨子航：ER 图我第一次认真用 Chen 氏画，弱实体双框和标识联系双菱形一画出来，"快照离了作业稿不存在"这种事就不用嘴说了。规则版本化是我在实验 2 对比会上就想到的，这次落成表的时候发现 NULL 唯一键的坑，用 0 绕过去，这种细节只有真写 SQL 才碰得到。触发器是我坚持的，答辩时演示一条 DELETE 报错就够了。
- 丁浩然：我这次没画图，列了前端页面和接口清单，对着类图看每个页面要调哪个 Service。学生端"我的时间线"和老师端时间线走同一个 TimelineAssembler，只是权限不同，这样两边看到的一样多就是结构保证的，不是靠自觉。
- 孟甲：架构上我最坚持的是不做微服务，六个人一个进程。这次最大的体会是 LLM 生成 SQL 的价值和风险都很具体：省了一小时打字，但它按"常见系统"补了一个我们红线明确不要的字段，而且把 ER 图批注里最要紧的三句话全丢了。以后给 LLM 的提示词里，约束必须单独列条，不能写成散文。
- 袁飞翔：我这次的活是拿验收标准逐条对图，挑出了粘贴事件没记位置。验证脚本 17 条断言我写了 7 条故意让它报错的，报错信息里带验收编号，以后回归测试一眼能看出是哪条挂了。起独立 MySQL 实例那步折腾了一会儿，但比改本机 root 口令安全。
- 张家森：录入 ER 图我学了 Graphviz，Chen 氏的下划线要用 HTML 标签，双框用 peripheries=2。录入时最难的是忍住不改，杨子航图上漏的枚举值我记在批注里而不是直接补进图。对比记录 30 条我一条条问清楚"谁改的、为什么"，答辩抽到谁都能答。
