# 手工原稿产出指引（实验 4）

> 指导书要求"根据 Sprint 1 目标手动拆分任务、对每个任务进行工时估算、使用 LLM 提供参考建议、对比说明差异、提交任务板截图和估算依据"。本目录放扑克牌估算的现场记录与人工拆分表。LLM 参考在人工估算全部结束之后再要，顺序反了整份材料作废。

## 输入

- `Exp02/04-最终版/用户故事卡.md` 的 Sprint 1 部分：16 张 Must、4 张 Should。
- `Exp02/04-最终版/验收标准表.md`：每张卡的验收条数就是测试任务的最小粒度。
- `Exp03/04-最终版/系统架构设计说明.md`：分包与负责人、四个手写算法的接口。

## 估算会流程（约两个半小时，线上或线下）

1. 产能 10 分钟。每人报未来四周每周能给项目的小时数，减去考试周和其他课作业，孟甲记产能表。乘以 0.8 得可承诺小时。
2. 扑克牌 60 分钟。20 张卡逐张估故事点，斐波那契 1 2 3 5 8 13。每张卡：负责人讲 1 分钟 → 同时亮牌 → 最高最低各说 1 分钟 → 再亮一轮 → 仍不一致取多数。张家森记每轮每人的牌。
3. 拆任务 50 分钟。每张卡按后端、前端、测试拆，每个任务不超过 8 小时，超过就再拆。任务写：编号、做什么、谁、小时、依赖。
4. 加横切任务 10 分钟。项目骨架、接口约定、测试环境、评审准备、代码审查、文档。
5. 相加对产能 10 分钟。超了砍 Should，再超砍 Must 的次要任务。砍掉的写清楚。
6. 建任务板 10 分钟。三列：待办、进行中、完成。用 GitHub Issues 或白板，拍照。

## 估算规则

- 故事点是相对大小，以 RULE-02（学生进作业先看规则）为 2 点基准。
- 小时是绝对值，含编码、自测、联调，不含会议。
- 四个手写算法各自单独成任务，不许并进别的任务里。
- 不确定的任务写区间，取上限入总数。
- 测试任务按验收标准条数估，每条手测 15 分钟起，集成或单测另加。

## 人工估算结束之后

1. 孟甲把最终版故事卡和分包表交给 LLM，让它独立给出任务拆分和工时，原样存 `02-LLM输出/01-LLM参考估算与任务建议.md`。不要把人工估算给它看。
2. 逐张卡对比人工与 LLM，差异超过 30% 的写原因，存 `03-对比与修改记录/估算对比记录.md`。
3. 人工估算为准。LLM 提醒到的遗漏任务可以补，补了要注明来源。

## 常见错误

- 先看 LLM 再出牌，整桌牌都被带偏。
- 任务只拆后端不拆测试，最后测试工时全是零。
- 前端工时按"一个页面两小时"估，编辑器和时间线组件不是普通页面。
- 相加超产能后不砍，Sprint 评审时全组一起挨批。
