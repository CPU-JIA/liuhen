# 留痕：课程作业 AI 使用备案与过程证据链平台

> 巢湖学院 2026-2027 学年第 1 学期《软件工程》实验课项目仓库。24 软工 2 班，6 人小组，第 2-13 周。

## 一句话

把高校学术诚信从"事后测 AI 率"转向"事前备案、过程留痕、证据可验"：学生按课程政策登记 AI 使用并自动留存写作过程，教师看得到时间线与贡献占比，学院申诉时有可校验的证据包。

## 为什么现在做

- 《学位法》自 2025 年起将利用 AI 代写列为可撤销学位的学术不端。
- 2026 年春季高校 AIGC 检测全面收紧，误判争议突出，经典散文被判 AI 率超过 60%，学生为"自证是人"反复付费。
- 教育部 2025 年 11 月《教师生成式人工智能应用指引》要求学生在提交作业中声明使用环节与具体方式，项目式学习须提交过程性材料。
- 中国学位与研究生教育学会 2026 年 5 月发布指南，要求 AI 使用声明写清工具名称、用途、环节、参数设置、验证过程。
- OECD《数字教育展望 2026》把"何种披露与溯源实践才算充分"列为开放问题，国内外尚无成熟产品。

完整调研见 `选题调研报告-2026.md`。

## 工作流：三件套不可少

课程规则是"人工为主、LLM 为辅"，教师随机抽查个人答辩。每个实验固定按下面顺序走：

1. 人先做：手写或手工整理，放入 `01-手工原稿`。手绘图拍照上传，手写笔记扫描或录入。
2. 再问 LLM：把 LLM 的原始输出原样保存到 `02-LLM输出`，文件头注明工具、日期、提示词。
3. 对比与修改：在 `03-对比与修改记录` 逐条写清采纳、部分采纳、拒绝及理由。
4. 定稿：合并为 `04-最终版`，附六段式实验报告。
5. 每次实验结束当天提交 git，提交信息写清实验编号与内容，例如 `exp01: 完成访谈记录与愿景说明`。

LLM 在本项目中承担的具体岗位，按课程允许范围：整理访谈记录、检查用户故事、生成 SQL 初稿、生成项目框架、生成测试初稿、给估算与优化建议、生成部署脚本初稿。核心算法、业务逻辑、回顾改进项、个人述职与总结必须人工完成。

## 导出 Word

```powershell
pwsh tools/export-docx.ps1 -Exp 01
```

会把 `docs/Exp01-*/04-最终版/*.md` 逐个导出为同名 `.docx`，放在同目录 `docx/` 下。需要本机已安装 Pandoc。

## 建任务板

分两步：`pwsh tools/create-sprint1-issues.ps1` 建 21 个 Issue 与标签；`pwsh tools/add-sprint1-issues-to-board.ps1` 把它们挂到 Project 看板并置待办。两个脚本都支持 `-DryRun` 只打印不执行，第二步需要 gh 令牌带 project 权限。

## 运行代码

Sprint 1 代码在 `project/`，本机运行、测试、容器化说明见 `project/README.md`。一句话：后端 `mvn spring-boot:run -Dspring-boot.run.profiles=dev`，前端 `pnpm dev`，冒烟 `bash project/scripts/smoke-sprint1.sh`。测试：后端 `mvn test`（单测加 JaCoCo 覆盖率），前端 `pnpm test`。
